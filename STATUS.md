**Сейчас зелёное:** 508 unit + 84 интеграционных (22 сентября, против локального Postgres
в докере) + 87 e2e (и 1 пропущенный — только для мобильного) · дев на `localhost:3000`

**База для тестов — локальная, а не живая.** `apps/web/vitest.config.ts` сам подгружает
`.env.local`, поэтому `pnpm test` без `DATABASE_URL` в окружении пишет в продакшен-базу.
Поднять свою и прогнать всё:

```bash
docker run -d --name sporim-test-db -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=sporim -p 55433:5432 postgres:16   # первый раз; потом docker start
export DATABASE_URL="postgres://postgres:postgres@127.0.0.1:55433/sporim"
pnpm --filter @sporim/web migrate                    # 11 миграций на чистой базе
pnpm --filter @sporim/web exec vitest run
```

Миграции создают роль `sporim_app` и расширение `citext` сами, так что обычного `postgres:16`
достаточно. Только юниты, без всякой базы: добавить
`--exclude "**/*.integration.test.ts" --exclude "**/node_modules/**"`.

**E2E тоже стоит гонять на ней:** страница спора читает базу, а ветка Xata засыпает и отвечает
`branch is hibernated` — два теста падают не по своей вине. Тот же `DATABASE_URL` в окружении
перед `pnpm --filter @sporim/web test:e2e` (переменные окружения важнее `.env.local`).

**Интеграционные против базы** просыпаются только когда в окружении есть `DATABASE_URL`;
без него `pnpm check` их пропускает и называет число поменьше — это не регрессия.
